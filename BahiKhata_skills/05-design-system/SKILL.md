# BahiKhata Design System Skill

## Purpose
Maintain a consistent visual language across Android and web surfaces.

## Invoke When
- Creating reusable UI.
- Changing colors, typography, spacing, components.
- Reviewing visual consistency.

## Inputs
- Existing design tokens
- Product brand direction
- UI requirements

## Outputs
- Design tokens
- Reusable components
- Usage rules

## Allowed
- Define typography, spacing, radii, elevation, semantic colors, buttons, fields, cards, dialogs, badges, and states.
- Extend existing tokens when necessary.

## Forbidden
- Per-screen arbitrary styling.
- Excessive gradients, shadows, animation, or decorative UI without purpose.

## Rules
1. Prefer semantic tokens.
2. Keep component variants limited.
3. Mobile readability has priority.
4. Visual hierarchy must reflect task priority.

## Verification
- New UI uses shared tokens/components.
- No unexplained one-off styles.
- Light/dark behavior, if supported, remains coherent.
